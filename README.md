### Framework

### Git

- 메인에서 develop 브랜치 생성하여 버전 관리 진행
    - develop 브랜치 명칭은 다음과 같은 구조를 지킨다
        - develop_ver_1.0
- develop 브랜치로부터 필요한 브랜치를 생성한다
- 브랜치는 총 3가지 종류의 브랜치가 존재한다
    1. feature
        1. 기능을 추가하고자 할 때 만드는 브랜치다
    2. update
        1. 잘못된 기능을 수정하기 위한 브랜치다
        2. 이미 존재하는 기능을 고도화할 때 사용하는 브랜치다
    3. HotFix
        1. 필요한 경우에 빠른 작업을 위해 메인에 직접 작업 할 수 있는 브랜치다
- 브랜치 네이밍 규칙
    - [feature, update, hotfix] / [명사 + _ + 동사]
        - EX) feature/monster_move
    - 동사와 명사중 필요에 따라 동사는 생략 가능
- 매주 월요일 목요일에 버전업을 진행한다
    - 예외 사항으로 최종 발표직전에는 버전업을 진행한다
- 최종 merge작업은 팀장이 진행한다
    - 팀장이 부득이한 경우로 작업을 진행하지 못할 경우 그 다음 권한을 가진 사람이 merge를 진행한다

### Coding Convention

- 헝가리언 표기법을 기본 문법으로 사용한다
- STL 컨테이너 이름은 뒤에 s를 붙인다
- 멤버변수에 m_를 붙인다
- 공유 되는 필터는 팀장이 관리를 한다

### Commit Convention

- 커밋 메시지에 자신이 작성한 코드의 대한 내용을 간단하게 기입한다
    - 어떤 내용의 작업을 했는지 알 수 있도록 작성한다
